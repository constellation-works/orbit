# Why — STD-12 Source style

Why each rule in [STD-12](STD-12.md) exists, tied to the incident behind it where there was one. Read the entry for a rule when its intent is unclear or before deviating. The rules themselves are in `STD-12.md`; this file explains them and adds none.

**Origin.** Two corrections of Daniel's on 2026-11-25, recorded as scribe entries. standard-18: `rust-cli-template`'s store had `contracts/` beside `db/` and `driver/`, and `apps/note/` beside `repository/notes.rs`; asked when a plural is right, the owner chose singular throughout and directed that it be recorded as a new standard and the rename relayed. standard-20: in `formation` at `b184ee3`, 31 of 47 Rust files had no blank line anywhere and 4 lines exceeded `max_width` 100 although `cargo fmt --check` passed; the owner pointed at `crates/formation-store/src/repository/identities.rs` and `messages.rs` as bad examples. Asked why the code was written that densely, the owner answered that Codex does this from time to time and not for the first time: a recurring habit of one provider, not a brief or a size budget. So the fix is gates that every provider's first commit meets, not guidance. The owner asked for a structure that supports other languages, with Rust as the start, hence a core and profiles.

- **R1 (singular names).** A singular name reads naturally where it is used (`driver::sqlite`, `repository::note`, `contract::Note`), and the Rust standard library leans singular (`fs`, `io`, `net`, `env`, `process`). A rule of "plural when the directory holds many peers" settles nothing, because `driver/` and `repository/` hold peers as much as `apps/` does. One rule with a short exception list ends the mixing.
- **R2 (named bindings).** A one-letter name tells the reader nothing about what it holds, and the dense files behind standard-20 used them freely. The proposal exempted the parameter of a one-expression closure; the lint that checks R2 (R14) cannot tell a closure parameter from any other binding, so the rule keeps one form that a machine can check. A generic type parameter is exempt because the lint does not flag one and `T` is idiomatic.
- **R3 (the formatter is the gate).** A formatter run in check mode settles layout without review, so the review can look at the code. Where the formatter is silent the rule must not fall back to review, because review is where the dense files got through.
- **R4 (blank lines between items).** rustfmt keeps blank lines it finds but never adds one, so a file written with none passes `cargo fmt --check`. The 31 files without a blank line in `formation` all passed it.
- **R5 (line width).** rustfmt leaves a statement it cannot fit within `max_width` unformatted and still passes the check: `crates/formation-store/src/repository/messages.rs` line 12 was such a line. Only a check on the source as written catches it.
- **R6 (file order).** A fixed order lets a reader find the types and the tests without scanning, and keeps a diff that adds a constant from scattering it.

Child modules are declared right after the header, so a file's module tree is the first thing a reader sees. In `orbit-common`'s `storage/sqlite/ledger/mod.rs` (ORB-28385) the `mod` lines and `pub use` came after its types; the Rust profile's gated rule is the Rust form of this order (scribe standard-25).
- **R7 (visible steps).** A function whose steps run together hides where one ends; an error handled several lines after the call that raised it hides which call can fail.
- **R8 (a guarantee gets a name).** In `formation`'s `identities.rs`, creating a missing key relied on a concurrent creator winning and both callers reading the winner's key, and nothing named that. A named function states the guarantee where it is called. The rule is narrow on purpose: it must not invite a helper for every few lines.
- **R9 (no unnamed tuple of three or more).** A caller of a function returning `(a, b, c)` must remember the order, and two values of one type can swap silently. A named type says which is which.
- **R10 (embedded SQL).** A long statement on one line cannot be read or diffed, and a bare `100` in a query does not say whether it is a page size or a cap.
- **R11 (rustfmt at width 100).** 100 is rustfmt's default and Google's Rust style guide's width, so most Rust code already meets it. Only stable options, because CI builds on the stable toolchain and stable rustfmt ignores an unstable option with a warning.
- **R12 (blank-line script).** `blank_lines_lower_bound` would do it, but on rustfmt 1.9.0-stable it warns "unstable features are only available in nightly channel" and is ignored.
- **R13 (line-width script).** `error_on_line_overflow` would make rustfmt fail on R5's case, but it is nightly-only on the same rustfmt.
- **R14 (min_ident_chars).** Clippy's `min_ident_chars` flags single-letter bindings, closure parameters and loop variables included, and leaves generic type parameters alone (checked on clippy 0.1.95). Its default allow-list exempts `i`, `j`, `x`, `y`, `z`, `w` and `n`, which would let most of the dense code through, so the list is emptied.
- **R15 (no glob imports).** From Google's Rust style guide (section "Don't use glob imports"): a glob hides where a name comes from and can shadow a name imported from elsewhere. The lint's default exceptions match the guide's for tests and re-exports. The guide also says defining preludes should be avoided, so a project prelude is not an exception.
- **R16 (one module per use).** From Google's Rust style guide ("A `use` statement should import items from one module", rustfmt's `imports_granularity = Module`). One module per statement makes an import's source visible at a glance and makes an added import one changed line. The rustfmt option is nightly-only, hence the script.
- **R17 (types bare, functions qualified).** From Google's Rust style guide ("Type names should be imported and used unqualified", "Qualify calls to top-level functions with a module name"): a type name is distinctive on its own, while a bare function name (`open`, `read`) does not say what it acts on.
- **R18 (documented public items).** Google's Rust style guide asks for documentation comments on public APIs and suggests the `missing_docs` lint for it, and asks that a comment add what the code does not already say. The lint makes presence a gate; content stays a review.
- **R19 (`rustfmt::skip`).** Google's Rust style guide allows opting out of formatting only for manual alignment and generated code, never for a personal style choice. The comment makes each skip reviewable, and the script makes the comment present.
- **R20.** Child modules and re-exports come first, so a file's structure shows in its opening lines; `orbit-common`'s `storage/sqlite/ledger/mod.rs` had them after its types. The order is one clippy can state (modules, then `use`, then everything else), so the rule is a gate rather than review, and rustfmt already sorts the names within each group (scribe standard-25, ORB-28385).
- **R21.** A reader finds what a type does beside its definition; an item between a type and its impls, or a project trait impl above a standard-library one, makes them hard to find. A script can check the order, so it is a MUST (scribe standard-26).
- **R22.** A reader finds an impl's constructors, then its builder steps, then its reads and its mutations, in the same place in every file. scribe's composition.rs (at e203820) mixed constructors, accessors and views in one impl. A script can read each method's receiver, return type, name and visibility, so the order is a gate (scribe standard-26).
- **R23.** A literal in declaration order can be checked against the struct by position, and a swap of two fields of the same type is otherwise easy to miss. Clippy states the order, so the gate is a lint (scribe standard-26).
- **R24.** A file is named for what it holds, and a file with two subjects has no name that fits both. scribe's crates/scribe-core/src/composition.rs (at e203820) is 610 lines, under STD-02 §R18's size threshold, and holds four subjects, so the size heuristic does not catch it. Review-only: a gate cannot tell one subject from two (scribe standard-26).
- **R25.** A reader follows a file top-down, so the flow reads in the order it runs when each helper follows its caller. Which function is the entry point is a judgement, so review-only (scribe standard-26).
- **R26.** `super::super` reaches an item through two parents, which a reader has to unwind; `crate::` names it from the root. Measured 2026-11-26 by text match: scribe has 11 such lines in 11 of 449 files, and formation and rust-cli-template have none. Orbit has 1,793 occurrences in 541 files. A glob-import rule is not added: R15 already holds it. Scribe entry standard-27 (scribe standard-27).

B replaces the single everything-else group with the groups this order needs, so a macro, a constant or a type out of place is flagged by the gate rather than left to review (scribe standard-26).

Left out of the Rust profile because STD-02 already holds them: an enum over a boolean mode parameter (§R36), no abbreviations (§R37), `expect` over `unwrap` (§R13). Left out on purpose, and Daniel saw both: a function-length cap, and Google's rule against implementation in non-leaf modules, which conflicts with the settled `driver/sqlite/mod.rs` holding its open call.
