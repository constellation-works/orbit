# CLI command evidence

The help inventory contains 164 command nodes: 139 terminal paths and 25 parent groups. Of the terminal paths, 131 have an observed successful isolated CLI process case with asserted behavior; eight are explicitly excluded below. Parent-group help and parsing are grammar evidence only; the executable default `doctor` and query-form `search` are separately recorded below. The map contains 73 terminal paths with captured argv evidence and 58 additional terminal paths with manually reviewed named passing process evidence. This is path coverage for the stated scenarios, not exhaustive flag, state, provider, platform, or workflow coverage.

Evidence comes from actual `QA_CLI` argv records emitted only after successful child commands, the completed 1,071-test CLI run, and supplemental passing process targets. Manually reviewed cases were followed through fixture helpers, unconditional branches, and assertions, then matched to a named passing test. Source literals and parser snapshots were discovery candidates only and are not counted here. Later tests retain their names after splitting by command family.

The fixtures isolate HOME, USERPROFILE, XDG configuration, registry and workspace data, and clear inherited authority. Provider tests use synthetic executables or deterministic replacement graphs; they do not certify real provider invocation. Runtime APIs used to establish a consumer baseline or workflow-failure block are fixture setup; the listed command behavior is executed through the real CLI.

The final aggregate at the pre-rebase local delivery snapshot `9d24863d9` completed on 2026-10-03 with **1,071 passed, 0 failed, 0 ignored**, across **54 suite summaries**, exit 0. Opt-in tracing emitted **145 actual successful argv records**. The path map combines those records with the earlier isolated QA runner captures and reviewed named passing cases; the aggregate count alone is not evidence for a command path. Two platform-only integration targets contain zero cases on Mac and provide no Linux evidence.

## Functional limits

- `run cancel` proves a confirmed terminal-run no-op with no signal or provider stop; active cancellation is not certified on Mac by this matrix.
- `run ship` and `run auto` prove worker launch and completion through deterministic replacement graphs. `run ship-sweep` proves dry-run routing. They do not prove production delivery or remote dispatch.
- Consumer recovery/reset proves settings adoption and audited reset of baseline-only state. Retained-debt recovery, action reissue, history replay and executing-action reset refusals have separate Core tests and are not claimed as CLI process coverage here.
- `mcp listen` proves loopback listener startup and initialization. Its signal test falls back to CLI process supervision for an unadvertised tool, so that test is not successful listener tool-dispatch evidence.
- `update` proves a local fixture mirror check and checkout-build refusal. Live binary replacement, packaging and release publication are outside this matrix.
- Workflow assets have their own [workflow evidence](workflow-evidence.md); a CLI suite does not prove every workflow asset. MCP wire operations have their own [tool evidence](mcp-tool-evidence.md).
