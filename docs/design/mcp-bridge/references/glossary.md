# Glossary — Orbit MCP

| Term | Meaning |
|---|---|
| Accepting machine | The machine running the direct MCP server or federated mux; direct sessions are authoritative for registry lookup, runtime selection, Core validation, and audit, while the mux routes host-qualified calls to destination servers. |
| Audit context | Server-established invocation metadata passed with a tool call: trace, caller observations, process identity, and transport. |
| Caller machine label | `caller_machine_id` supplied by the SSH proxy or derived locally for audit. It is self-asserted unless a destination's forced-command SSH acceptance binds the caller to the key sshd authenticated. |
| Caller IP | Best-effort first field of `SSH_CONNECTION` for an SSH-originated session. It is not a stable machine identity. |
| Direct SSH stdio proxy | The policy-free local process that runs `ssh -T` with inherited standard streams and remote `orbit mcp serve`. |
| `host/local` | Fallback audit label when Orbit cannot derive a persisted machine identity. |
| Process identity | `process_machine_id` and `process_host_id` derived by the accepting server from its local registry. |
| Tool-call audit boundary | The single Core seam crossed by every direct-server `tools/call`, including unknown raw names, with one per-call trace and outcome row. Federated discovery and routing are handled by the mux before a destination call. |
| SSH MCP | A remote MCP session carried directly over SSH stdio and recorded with transport `ssh-mcp`; its requested authority is capped by the destination's callers policy. |
| Trace ID | Fresh per-call correlation identifier generated by the MCP adapter and persisted through Core audit. |
| Workspace selector | Stable workspace value supplied by tool input or MCP initialization metadata and resolved only by the accepting server. Federated calls use a copied host-qualified `hm_…/ws_*` selector. |
