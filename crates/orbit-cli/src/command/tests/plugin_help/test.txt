Run a plugin's conformance goldens against this Orbit

Usage: orbit plugin test [OPTIONS] <DIR>

Arguments:
  <DIR>
          Plugin directory holding `plugin.yaml`

Options:
      --first-party
          Treat the source as a verified first-party checkout, so an `origin: orbit` manifest runs as it would after a verified install

      --root <ROOT>
          Override the Orbit root directory (highest precedence)

      --grant <GRANTS>
          Consent to these grants for this run (repeatable, comma-separated): fs, network, env_pass, orbit_tools, unsandboxed. Same names as `orbit plugin enable --grant`. Required when the manifest asks for an unconfined backend, an absolute write root, `network: any`, or `env_pass`, unless `--accept-requested` is set. Does not record a host grant

      --workspace <SELECTOR>
          Select a workspace by registered name, logical ID (`ws_*`), or absolute checkout path. Distinct from `--root`, which overrides the Orbit data directory. Only active workspaces may be bound; commands fail if the workspace status is not active

      --accept-requested
          Run under the profile the manifest requests, including an unconfined backend, absolute write roots, `network: any`, and `env_pass`. Does not record a host grant

      --case <NAME>
          Run exactly one named conformance case

      --update-goldens
          Replace mismatched `expect.output` values with the actual output

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

  -h, --help
          Print help (see a summary with '-h')
