Run an arbitrary job by ID

Usage: orbit run job [OPTIONS] <JOB_ID>

Arguments:
  <JOB_ID>
          Job ID from the catalog, or a direct path to a schemaVersion 2 job YAML

Options:
      --input <INPUT>
          Input key=value pairs passed to all job steps (repeatable). Example: --input task_id=T123 --input base=main

      --wait
          Wait for a terminal run state for up to 3600 seconds by default. Exit nonzero on wait expiry or an unsuccessful run; expiry reports wait_timeout=true with the actual run state and leaves the run active

      --timeout-seconds <TIMEOUT_SECONDS>
          Wait deadline in seconds (0..=21600); requires --wait

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

Examples:
  orbit run job task_auto_pipeline
  orbit run job task_auto_pipeline --input mode=local
  orbit run job task_pilot_pipeline --wait
  orbit run job task_pilot_pipeline --input crew=luna --json

There is no `--crew` flag: crew selection is a run input, `--input crew=<name>`.
That picks this run's resolved crew; an activity with an explicit `crew` or
`crew_config_key` pool still routes there instead. Check `activity_provenance` in
`orbit run show <RUN_ID> --json` for what actually dispatched.

The run is submitted to a detached worker and the command returns as soon as it is durable.
Inspect it with `orbit run history -j <JOB_ID>` and `orbit run show <RUN_ID>`.
