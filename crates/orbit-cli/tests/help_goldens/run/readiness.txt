Explain why backlog tasks can or cannot start in auto-drain

Usage: orbit run readiness [<TASK_ID>...] [OPTIONS]

Arguments:
  [TASK_ID]...
          Optional task IDs to explain. Omit to inspect a bounded backlog snapshot

Options:
      --concurrency <N>
          Leaf-run concurrency to evaluate. Omit for the live local drain's ceiling, else a live pull drain's, else 5

      --limit <N>
          Maximum tasks to explain, including an explicit selection (1-500)
          
          [default: 50]

      --allow-crew <CREW>
          Evaluate as if the drain were restricted to these configured crews. Repeatable and comma-separated; omitted, the live drain's own crew restriction applies (none when no drain is live or it has none)

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

This is a read-only snapshot: it does not reserve work, reconcile stale runs,
submit a run, or mutate tasks. Eligible tasks are not guaranteed to start.
An explicit --concurrency overrides the live drain's ceiling; --allow-crew
previews a crew restriction without changing the drain.

Examples:
  orbit run readiness
  orbit run readiness TASK-123 TASK-124
  orbit run readiness --concurrency 8 --allow-crew sol --json
