Show recent job runs filtered by job, task, state or time

Usage: orbit run history [OPTIONS]

Options:
  -j, --job <JOB_ID>
          Filter to one job ID

      --root <ROOT>
          Orbit data directory to use (overrides every other source)

      --task <TASK_ID>
          Filter to runs whose input.task_ids array contains the task or whose top-level input.task_id matches it

      --workspace <SELECTOR>
          Active workspace to use: registered name, `ws_*` ID or checkout path

      --state <STATE>
          Filter to any of these comma-separated run states

      --since <SINCE>
          Only runs created at or after this RFC 3339 time or relative duration (24h, 7d)

      --limit <LIMIT>
          Maximum number of runs to show
          
          [default: 50]

      --no-reconcile
          Report stored run records as-is: skip stale-run reconciliation, which finalizes an orphaned pending or running run as interrupted, releases its task reservations, and settles with their owner the pull claims an ended drain or leaf left

      --incidents
          Show one row per incident: fold runs that failed only because a child failed into the run that failed on its own

      --failures
          One row per task and root cause: the root-cause run, its step and crew, the cause's first line in full, and `orbit run show` for that run

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - plain:  Untruncated text with tab-separated fields; a header row only with --header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

      --json
          Output as JSON (shorthand for --format json; always pretty-printed)

      --header
          Start plain output with a tab-separated header row (table output always has one)

  -h, --help
          Print help (see a summary with '-h')

JSON shape: {"runs":[<job-run>]}. --failures uses {"failures":[{"task_id","run_id","step","crew","cause","show"}]} instead.
ROLE says how a run was submitted: top-level directly, child by a parent run.
Run ids minted before role markers existed read as unmarked.
A gate or auto run that failed only because a child failed records the leaf it echoes in `.root_cause` ({leaf_run_id, task_id, step, code}); it is null for a run that failed on its own. --incidents folds every listed run that echoes the same leaf into one row, the leaf's own when it is listed: CASCADED counts the folded runs and `.cascaded_run_ids` names them. --failures folds the same runs into one row per task and root cause: RUN_ID, STEP and CREW are the root-cause run's, CAUSE is that run's error on one line with no 60-character cap, and SHOW is `orbit run show` for that run. --failures and --incidents cannot be combined.
Examples:
  orbit run history
  orbit run history -j task_local_pipeline --limit 20
  orbit run history --state failed,held --since 24h
  orbit run history --state failed --incidents
  orbit run history --state failed --failures
  orbit run history --json
  orbit run history --limit 200 --no-reconcile --json
