Drain the workspace backlog for a window

Usage: orbit run auto [OPTIONS]

Options:
      --for <DURATION>
          How long to keep admitting work, e.g. `30m`, `2h` (default: one pass)

      --concurrency <N>
          Maximum tasks in flight (default 5)

      --auto-concurrency <MODE>
          Forecast admission mode (default: `machine.auto_concurrency.mode`)
          
          [possible values: off, shadow, enforce]

      --complete
          Land shipped tasks and mark them `done` instead of leaving them in `review`

      --approve-proposed
          Approve `proposed` tasks that pass task-pilot verification

      --auto-fix
          Repair failing checks and conflicts on the pull requests this drain opens

      --review <LAYER>
          Add a review layer before landing when workspace policy has none. `before-landing` is recommended; `before-pr` is deprecated but still holds PR creation for a reviewer

          Possible values:
          - before-pr:      Hold PR creation for a reviewer, as `review.timing = before_pr` does. Deprecated: prefer `before-landing`; still honoured as before-PR
          - before-landing: Review the open PR before it lands, as `review.timing = before_landing` does. Recommended for new `--review` requests

      --allow-crew <CREW>
          Start only tasks on these crews (repeatable, comma-separated)

      --strict-worker-containment
          Require a systemd user scope for the coordinator and every worker

      --low-complexity-crews [<CREW>...]
          Crew pool for unassigned low-complexity tasks (`crew` or `crew:weight`)

      --medium-complexity-crews [<CREW>...]
          Crew pool for unassigned medium-complexity tasks (`crew` or `crew:weight`)

      --hard-complexity-crews [<CREW>...]
          Crew pool for unassigned hard-complexity tasks (`crew` or `crew:weight`)

      --xhard-complexity-crews [<CREW>...]
          Crew pool for unassigned xhard-complexity tasks (`crew` or `crew:weight`)

      --pull <SELECTOR>
          Claim work from this owner's backlog and hand results back as pull requests

      --host <HOST>
          Owner host for `--pull <workspace>` (name or `machine_id`)

      --claim-token <CLAIM_TOKEN>
          Workspace claim token (default: `ORBIT_WORKSPACE_CLAIM_TOKEN`)

      --stop
          Stop admitting new work; running tasks continue

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

Examples:
  orbit run auto
  orbit run auto --medium-complexity-crews grok,sol
  orbit run auto --for 4h
  orbit run auto --for 4h --concurrency 8
  orbit run auto --for 4h --complete
  orbit run auto --for 4h --auto-fix
  orbit run auto --for 4h --approve-proposed
  orbit run auto --for 2h --review before-landing
  orbit run auto --stop
  orbit run auto --pull hm_owner/ws_orbit --for 8h --concurrency 3
  orbit run auto --pull hm_owner/ws_orbit --for 8h --allow-crew sol,luna

Prints the run ID and returns; follow it with `orbit run show <RUN_ID>`.
Run-wide flags cover every task the window admits, even ones filed later.
Details: the orbit-orchestrate skill, references/orchestration.md.
