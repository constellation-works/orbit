Rebind this host to a checkout directory the operator already moved

Usage: orbit workspace rebind [OPTIONS] --path <DIR>

Options:
      --path <DIR>
          Existing Git checkout directory after the operator moved it

      --dry-run
          Validate and report the new binding without changing the checkout binding, pending rebind record or audit log; generation admission and lock bookkeeping can still write (default: apply)

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

Stop workspace runs and release claims before moving the directory. Remove retained Orbit-managed worktrees first. This command never moves files, changes the source remote, or changes another host. It requires the registered Git origin and .orbit identity, and an existing host store (orbit.db). Before moving a newly initialized checkout, run a runtime command such as `orbit tool run orbit.task.list --input '{}'` to initialize the host store. A missing store is refused before generation admission, with or without --dry-run, and writes nothing. `--dry-run` leaves the checkout's binding in the workspace registry and task store, the pending rebind record and the audit log unchanged; generation admission and registry lock bookkeeping can still write. Keep the host store outside the moved directory. Repeat the same command to finish an interrupted rebind.

Examples:
  orbit --workspace <name> workspace rebind --path /new/checkout --dry-run --json
  orbit --workspace <name> workspace rebind --path /new/checkout --json
