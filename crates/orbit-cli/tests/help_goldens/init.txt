Initialize the global Orbit root (~/.orbit)

Usage: orbit init [OPTIONS]

Options:
      --force
          Reset the global Orbit root (~/.orbit/) to shipped defaults before initialization, including executor sandbox settings and the machine identity. Non-interactive resets require --machine-name and --task-prefix

      --host-prerequisites-only
          Prepare the Linux host without creating a machine identity or writing Orbit state

      --skip-host-prerequisites
          On Linux, leave Bubblewrap packages and AppArmor profiles to the host's administrator. Orbit still seeds `linux-bwrap` executors, and dispatch stays fail-closed until `orbit doctor providers` reports the sandbox ready
          
          [env: ORBIT_SKIP_HOST_PREREQUISITES=]

      --non-interactive
          Skip interactive prompts. config.toml is still seeded from detected agent surfaces, but a CI runner that pipes nothing into stdin will not hang

      --machine-name <MACHINE_NAME>
          Operator-chosen display name for this machine. Used only when no identity exists yet or --force resets it. Required with --non-interactive on a fresh machine or reset; interactively, the OS hostname is the default

      --task-prefix <PREFIX>
          Immutable task-id namespace for this machine (2-5 uppercase ASCII letters). Required on first init or with --force; reserved artifact namespaces cannot be chosen

      --human-name <NAME>
          Name of your human crew, the crew for operator work that no drain or task pilot picks up. Used only when no human crew exists yet; otherwise the OS user is the default (offered at an interactive prompt, taken as-is without a terminal or with --non-interactive)

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

On Linux, sandbox preparation failures warn and initialization continues.
linux-bwrap dispatch stays blocked until orbit doctor providers reports
the sandbox ready. Fix the cause named in the warning,
then retry with orbit init --host-prerequisites-only. JSON output includes
linux_sandbox.status (ready, skipped, or not_ready) and its reason.
