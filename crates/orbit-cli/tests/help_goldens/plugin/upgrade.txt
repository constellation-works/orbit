Upgrade an installed plugin and review requested-permission changes

Usage: orbit plugin upgrade [OPTIONS] <NAME> [SOURCE]

Arguments:
  <NAME>
          Installed plugin namespace

  [SOURCE]
          Replacement source; defaults to the source recorded at install time

Options:
      --digest <DIGEST>
          `sha256:<hex>` the archive at an `https://` source must hash to. Required for such a source, including one recorded at install time: the replacement archive is a new download and needs its own pin

      --root <ROOT>
          Override the Orbit root directory (highest precedence)

      --grant <GRANTS>
          Complete permission grant set authorizing and enabling the new manifest (repeatable, comma-separated): fs, network, env_pass, orbit_tools, unsandboxed. Without it, widened requests disable the plugin and clear its grants. Scope fs to particular roots with `fs=<root>[,<root>]`, as `orbit plugin enable --grant` documents

      --workspace <SELECTOR>
          Select a workspace by registered name, logical ID (`ws_*`), or absolute checkout path. Distinct from `--root`, which overrides the Orbit data directory. Only active workspaces may be bound; commands fail if the workspace status is not active

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

  -h, --help
          Print help (see a summary with '-h')
