Upgrade an installed plugin and review requested-permission changes

Usage: orbit plugin upgrade [OPTIONS] <NAME> [SOURCE]

Arguments:
  <NAME>
          Installed plugin namespace

  [SOURCE]
          Explicit replacement source (required); recorded sources are not trusted

Options:
      --digest <DIGEST>
          `sha256:<hex>` the archive at an `https://` source must hash to. Required for such a source: the replacement archive is a new download and needs its own pin

      --grant <GRANTS>
          Complete permission grant set authorizing and enabling the new manifest (repeatable, comma-separated): fs, network, env_pass, orbit_tools, unsandboxed. Without it, widened requests disable the plugin and clear its grants. Scope fs to particular roots with `fs=<root>[,<root>]`, as `orbit plugin enable --grant` documents

      --allow-build
          Consent to build this source on this host. A `git+<url>#<full commit id>` source whose manifest declares `spec.build` is refused without it, even when the commit and command are unchanged; the refusal prints the build plan to review. Consent covers this one command and never comes from a pin or config

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header
