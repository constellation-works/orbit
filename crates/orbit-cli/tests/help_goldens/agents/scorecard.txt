Show one role's scorecard rows by crew and model

Usage: orbit agents scorecard [OPTIONS] --role <ROLE>

Options:
      --role <ROLE>
          The agent role to score
          
          [possible values: orchestrators, implementers, reviewers, pilots]

      --root <ROOT>
          Orbit data directory to use (overrides every other source)

      --window <WINDOW>
          Count work in this period ending now
          
          [default: 30d]
          [possible values: 1h, 24h, 7d, 30d, 90d, all]

      --workspace <SELECTOR>
          Active workspace to use: registered name, `ws_*` ID or checkout path

      --min-support <MIN_SUPPORT>
          Units of work a row needs before it is ranked
          
          [default: 10]

      --by-type
          Show implementers split by task type within each tier

      --shadow
          Compare recorded draw shares with the shares the recorded factor would have given

      --per-task
          Export one row per implemented task for offline analysis

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - plain:  Untruncated text with tab-separated fields; a header row only with --header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

      --json
          Output as JSON (shorthand for --format json; always pretty-printed)

      --header
          Start plain output with a tab-separated header row (table output always has one)

  -h, --help
          Print help (see a summary with '-h')

The table shows each row's units, score and term counts; --json carries every rate per 100
units and the term definitions. Follow a row to its tasks with
`orbit agents show --role <role> --crew <crew>`.

`--by-type --shadow` (implementers only) replaces the cell matrix with each crew's static,
drawn and would-be share from recorded draws in the window.

`--per-task` (implementers only) exports one row per implemented task for offline analysis;
use --json for the machine-readable export.
