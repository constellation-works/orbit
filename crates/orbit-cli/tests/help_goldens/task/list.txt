List tasks with optional filters

Usage: orbit task list [OPTIONS]

Options:
      --root <ROOT>
          Orbit data directory to use (overrides every other source)

      --status <STATUS>
          Filter by one or more statuses (comma-separated). Opt-in: with no `--status`, tasks of every lifecycle status are listed under a status-aware rule (non-terminal tasks first, then terminal tasks)

          Possible values:
          - proposed:    Awaiting human approval before entering the backlog
          - backlog:     Approved and queued for work; not yet started
          - in-progress: Actively being worked on
          - review:      Implementation complete; awaiting review/merge
          - done:        Accepted and closed. Terminal; reopening requires a human operator to use `task update --force`
          - blocked:     Temporarily paused (waiting on a dependency or decision)
          - archived:    Soft-deleted. Terminal; restoration requires a human operator to use `task update --force`
          - rejected:    Declined. Ordinary edits may return it to backlog or in-progress; other transitions require a human operator to use `task update --force`
          - someday:     Future-scoped — wanted but not yet actionable. Agents skip someday tasks

      --all
          Deprecated no-op: task listing is status-neutral by default, so `--all` is no longer required to see every lifecycle status. Accepted for backward compatibility and ignored

      --workspace <SELECTOR>
          Active workspace to use: registered name, `ws_*` ID or checkout path

      --limit <LIMIT>
          Maximum number of tasks to return (default 50). Must be at least 1. Under the default status-aware rule, non-terminal tasks are listed first (newest first), followed by terminal tasks (newest first)
          
          [default: 50]

      --priority <PRIORITY>
          Filter by priority level
          
          [possible values: low, medium, high, critical]

      --type <TASK_TYPE>
          Filter by task type (feature, bug, refactor, chore)

          Possible values:
          - feature
          - bug:      An attributable defect; lineage is recorded through typed task relations
          - refactor
          - chore

      --origin <ORIGIN>
          Filter by task origin (operator_request, orchestrator_initiative, automation); tasks without a recorded origin never match

          Possible values:
          - operator_request:        A human operator asked for the work
          - orchestrator_initiative: An orchestrator decided the work was needed on its own
          - automation:              Filed by automation: an auto-task, routine, sweep or other system filer

      --parent <PARENT_ID>
          Filter to subtasks belonging to a parent task

      --job-run-id <JOB_RUN_ID>
          Filter by job run ID

      --tag <TAGS>
          Filter by tag. Repeat for AND semantics

      --ref <EXTERNAL_REF>
          Filter by exact external reference in `system:id` form

      --has-ref <HAS_REF>
          Filter by external reference system

      --ready
          Keep only tasks whose dependencies are already satisfied

      --runs-on <RUNS_ON>
          Filter by effective host OS: tags intersected with the stored crew executor; unrestricted tasks match, unresolved crews and conflicts do not

          Possible values:
          - linux:   Linux hosts
          - macos:   macOS hosts
          - windows: Windows hosts

      --path <PATH>
          Filter to tasks whose `context_files` selectors apply to this path. Selector forms supported: `file:`, `dir:`, `symbol:`, and bare paths. Bidirectional containment — passing a directory matches every selector under it

      --ops
          Output signal-tier JSON (id, title, type, status, priority only)

      --full
          Show all table columns in text output

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - plain:  Untruncated text with tab-separated fields; a header row only with --header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

      --json
          Output as JSON (shorthand for --format json; always pretty-printed)

      --header
          Start plain output with a tab-separated header row (table output always has one)

  -h, --help
          Print help (see a summary with '-h')

Examples:
  orbit task list
  orbit task list --limit 100
  orbit task list --status backlog
  orbit task list --status in-progress,review
  orbit task list --type feature
  orbit task list --origin operator_request
  orbit task list --priority high
  orbit task list --parent T12345678-123456
  orbit task list --ref jira:ENG-1234
  orbit task list --has-ref jira
  orbit task list --tag perf --tag bench
  orbit task list --path src/auth/login.rs
  orbit task list --json
