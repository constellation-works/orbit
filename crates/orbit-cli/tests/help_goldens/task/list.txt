List tasks with optional filters

Usage: orbit task list [OPTIONS]

Options:
      --status <STATUS>
          Filter by one or more statuses (comma-separated)

          Possible values:
          - proposed:    Awaiting human approval before entering the backlog
          - backlog:     Approved and queued for work; not yet started
          - in-progress: Actively being worked on
          - review:      Implementation complete; awaiting review/merge
          - done:        Accepted and closed (terminal)
          - blocked:     Temporarily paused (waiting on a dependency or decision)
          - archived:    Soft-deleted (terminal)
          - rejected:    Declined
          - someday:     Future-scoped — wanted but not yet actionable

      --scheduled
          List future-scheduled tasks soonest first, including proposed tasks labelled by status

      --not-before-from <NOT_BEFORE_FROM>
          Inclusive lower schedule bound (RFC 3339 with an offset)

      --not-before-until <NOT_BEFORE_UNTIL>
          Inclusive upper schedule bound (RFC 3339 with an offset)

      --all
          Deprecated no-op; accepted and ignored

      --limit <LIMIT>
          Maximum number of tasks to return (default 50). Must be at least 1
          
          [default: 50]

      --priority <PRIORITY>
          Filter by priority level
          
          [possible values: low, medium, high, critical]

      --type <TASK_TYPE>
          Filter by task type (feature, bug, refactor, chore)

          Possible values:
          - feature
          - bug:      An attributable defect; lineage is recorded through typed task relations
          - refactor
          - chore

      --origin <ORIGIN>
          Filter by task origin (operator_request, orchestrator_initiative, automation); tasks without a recorded origin never match

          Possible values:
          - operator_request:        A human operator asked for the work
          - orchestrator_initiative: An orchestrator decided the work was needed on its own
          - automation:              Filed by automation: an auto-task, routine, sweep or other system filer

      --parent <PARENT_ID>
          Filter to subtasks belonging to a parent task

      --job-run-id <JOB_RUN_ID>
          Filter by job run ID

      --tag <TAGS>
          Filter by tag. Repeat for AND semantics

      --ref <EXTERNAL_REF>
          Filter by exact external reference in `system:id` form

      --has-ref <HAS_REF>
          Filter by external reference system

      --ready
          Keep only tasks whose dependencies are already satisfied

      --runs-on <RUNS_ON>
          Filter by effective host OS: tags intersected with the stored crew executor; unrestricted tasks match, unresolved crews and conflicts do not

          Possible values:
          - linux:   Linux hosts
          - macos:   macOS hosts
          - windows: Windows hosts

      --path <PATH>
          Filter to tasks whose `context_files` selectors apply to this path

      --ops
          Output signal-tier JSON (id, parent_id, title, type, status, priority, complexity)

      --full
          Show all table columns in text output

      --pilot-warnings
          Keep proposed tasks held by pilot warning findings

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

Status meanings, lifecycle and listing-order rules: installed Orbit skill `references/task-fields.md`.

Examples:
  orbit task list
  orbit task list --limit 100
  orbit task list --status backlog
  orbit task list --status in-progress,review
  orbit task list --type feature
  orbit task list --origin operator_request
  orbit task list --priority high
  orbit task list --parent T12345678-123456
  orbit task list --ref jira:ENG-1234
  orbit task list --has-ref jira
  orbit task list --tag perf --tag bench
  orbit task list --path src/auth/login.rs
  orbit task list --json
