List backlog/proposed tasks you can pick up without colliding with work in flight

A task is eligible when its context-file lock surface overlaps no in-progress or review task's surface — the same lock test automatic dispatch applies. Nothing else is checked: not dependencies, complexity, groups or crew, and candidates are not checked against each other. Read-only: nothing is reserved, reconciled or changed.

Usage: orbit task eligible [OPTIONS]

Options:
      --status <STATUS>
          Candidate statuses (comma-separated). Default: backlog and proposed
          
          [possible values: backlog, proposed]

      --path <PATH>
          Keep only candidates whose `context_files` selectors apply to this path, matched as `orbit task list --path` matches

      --limit <LIMIT>
          Maximum eligible tasks to list (default 50). Must be at least 1
          
          [default: 50]

      --explain
          Also list the held-back candidates, each with the overlapping file and the in-progress or review task holding it

  -h, --help
          Print help (see a summary with '-h')

Global options (see 'orbit --help' for descriptions):
  --root <ROOT>
  --workspace <SELECTOR>
  --format <MODE>
  --json
  --header

Examples:
  orbit task eligible
  orbit task eligible --status proposed
  orbit task eligible --path crates/orbit-cli
  orbit task eligible --explain
  orbit task eligible --json
