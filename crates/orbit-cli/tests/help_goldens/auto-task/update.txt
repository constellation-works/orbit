Update an existing definition (present fields only)

Usage: orbit auto-task update [OPTIONS] <NAME>

Arguments:
  <NAME>
          Definition name

Options:
      --description <DESCRIPTION>
          New description

      --root <ROOT>
          Override the Orbit root directory (highest precedence)

      --cron <CRON>
          New 5-field cron expression (mutually exclusive with `--every-minutes`)

      --workspace <SELECTOR>
          Select a workspace by registered name, logical ID (`ws_*`), or absolute checkout path. Distinct from `--root`, which overrides the Orbit data directory. Only active workspaces may be bound; commands fail if the workspace status is not active

      --every-minutes <EVERY_MINUTES>
          New interval in minutes (mutually exclusive with `--cron`)

      --deliveries-landed <DELIVERIES_LANDED>
          Delivery trigger JSON: branch, threshold, max_wait_minutes, coverage; optional owner_machine (defaults to this workspace's registered owner machine), max_items, retries

      --dedupe <DEDUPE>
          New dedupe policy

          Possible values:
          - skip-if-open: Skip the fire while a previously-created instance is still open, so a stalled backlog never accumulates identical tasks (the default)
          - always:       Always fire, even if a prior instance is still open

      --title <TITLE>
          New task title

      --body <BODY>
          New task body

      --criterion <CRITERIA>
          Replace acceptance criteria. Repeat for multiple

      --type <TASK_TYPE>
          New task type

          Possible values:
          - feature
          - bug:      An attributable defect; lineage is recorded through typed task relations
          - refactor
          - chore

      --tag <TAGS>
          Replace tags. Repeat for multiple

      --required-tools <REQUIRED_TOOLS>
          Replacement exact canonical tools copied to minted tasks (empty clears)

      --priority <PRIORITY>
          New priority
          
          [possible values: low, medium, high, critical]

      --complexity <COMPLEXITY>
          New assessed complexity for minted tasks

          Possible values:
          - low
          - medium
          - hard
          - xhard:  Reserved top tier for the most capable (and most expensive) crews. Spelled `xhard` everywhere, so neither serde's snake_case rename nor clap's kebab-case value naming may split it into `x_hard`/`x-hard`

      --crew <CREW>
          New crew override

      --status <STATUS>
          New minted-task status

          Possible values:
          - proposed:    Awaiting human approval before entering the backlog
          - backlog:     Approved and queued for work; not yet started
          - in-progress: Actively being worked on
          - review:      Implementation complete; awaiting review/merge
          - done:        Accepted and closed. May be reopened by an explicit status edit
          - blocked:     Temporarily paused (waiting on a dependency or decision)
          - archived:    Soft-deleted. Can be restored to any other status
          - rejected:    Declined. Can be reclassified to any other status
          - someday:     Future-scoped — wanted but not yet actionable. Agents skip someday tasks

      --waive-batch <WAIVE_BATCH>
          Waive a settled failed delivery batch, retaining its coverage gap

      --waiver-reason <WAIVER_REASON>
          Required explanation for a batch waiver

      --format <MODE>
          Output format (default: auto — a table on a terminal, plain text when piped)

          Possible values:
          - auto:   Decide from the sink: a table on a terminal, plain text otherwise
          - table:  Aligned columns with a header
          - plain:  Untruncated text with tab-separated fields and no header
          - json:   A single JSON document
          - ndjson: One complete JSON document per line

      --json
          Output as JSON (shorthand for --format json; always pretty-printed)

  -h, --help
          Print help (see a summary with '-h')
