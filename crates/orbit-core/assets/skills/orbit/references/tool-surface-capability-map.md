# Tools: capability map

## Capability map

| Need | MCP / registered tool | CLI administration |
|---|---|---|
| Workspace discovery | `orbit_workspace_list`; `include: ["crews"]` adds each workspace's configured crews (or `crews_error`) | `orbit workspace list/show`; `orbit config show` |
| Task create/read/update | `orbit_task_add/list/show/update` | Registered `orbit.task.*` tools preserve agent attribution; lifecycle writes use `orbit.task.update` with `status` |
| Pick up work without collisions | `orbit_task_eligible` (read only; `explain: true` names each blocking selector and holder) | `orbit task eligible`: backlog/proposed tasks whose lock surface overlaps no in-progress or review task. Lock overlap is the only test; check dependencies yourself |
| Task attachments | `orbit_task_artifact` action `put`, `orbit_task_artifact` action `get` | Task artifact commands; source path is on the executing host and must resolve inside the workspace checkout |
| Retrieval | `orbit_search` | `orbit search`; `orbit search reindex` rebuilds the index |
| Agent scorecards | `orbit_agents_scorecard` and `orbit_agents_show` (`role`: `implementers`, `reviewers`, or `pilots`; optional `until`); `orbit_agents_ci_failures` (optional `window`, `until`, `task`, `class`) | `orbit agents scorecard --role <role>` and `orbit agents show --role <role> --crew <crew>`, both with optional `--until`; `orbit agents ci-failures` lists required-check failures by cause (see [CI failures by cause](tool-surface-scorecards.md#ci-failures-by-cause)). |
| Codebase risk | `orbit_codebase` action `analytics`, `orbit_codebase` action `show`, and `orbit_codebase` action `related` (opt-in `--toolset codebase` or `machine.mcp.toolsets` in the operator profile; included in `agent` and `reader`; always reachable via `orbit tool run orbit.codebase`) | `orbit codebase analytics`, `orbit codebase show <path>`, and `orbit codebase related <path>`. The analytics and show metrics, attribution, filters, and response fields are described below. Related paths are landed co-change |
| Friction | `orbit_friction action add/update`; list with `orbit_search` `kind: "friction"` and no `query`; move to the owning workspace with `update` `rehome_to` | `orbit friction list`, `rehome`, and additional show/stats/tags/resolve commands |
| Evolution costs | `orbit.evolution.add` records an interactive cost event; `orbit.evolution.list` ranks capability-gap signatures by recorded cost; `orbit.evolution.show` inspects one record and its occurrences | `orbit evolution add --event <JSON>`, `list [--state <state>] [--since <time>]`, and `show <id>`; operator-only `decline <id>` suppresses proposals for a signature. Use this for repeated costs caused by a missing capability; use [Friction](friction.md) for defects and contradicted assumptions |
| Submit explicit tasks | `orbit_workflow` action `ship` (review-only; no completion input) | `orbit run ship`, `run auto` (`--auto-fix` also has an operator-only dashboard checkbox; no MCP auto-fix start input) |
| Forecast mode for a local drain | `orbit_workflow` action `auto` with `action: "start"` accepts `auto_concurrency: "off"`, `"shadow"` or `"enforce"`; omission follows the configured host mode each admission pass. Pull drains refuse this override and use the executor host mode. | `orbit run auto --auto-concurrency <MODE>`; omission has the same live host default. Explicit overrides and inheritance source (`explicit` or `configured`) survive restart/resume without writing config; host thresholds and provider-limit policy refresh next pass, caching unchanged config by mtime and retaining the previous policies with a warning on invalid config; run show and readiness expose `mode`, `source` and the current `configured_mode`. This selects forecast policy only: normal operator authority, worker ceiling and host thresholds still apply. |
| Control auto drains | `orbit.workflow.auto` (`orbit_workflow` action `auto`): `status` is a read available to a live resident cycle for its covered workspaces without any granted right; other workspaces are refused as `resident_scope_refused` (see [Resident cycle](resident-cycle-act.md)). `start`, `stop` and `resize` are operator-only. A start may set `approve_proposed: true` to approve qualifying proposals per admission pass; it never approves `no-drain` or `no-auto-approve` tasks. After a lost start reply, read status and inspect `drain_run_id` and `queued_drains` before retrying; status is a snapshot and performs no reconciliation or submission. `stop` cancels queued, never-started coordinators and stops admissions on live drains; dispatched children keep running. `force: true` also cancels live drains and in-flight work. `resize` changes a live local or pull drain's worker ceiling in place; lowering it pauses new admissions while existing children finish. It requires `concurrency`; optional `id` selects a run and `if_revision` guards concurrent changes. | Start: `orbit run auto`; stop admissions: `orbit run auto --stop`; status: `orbit run readiness`; resize: `orbit run concurrency <run-id> --set <N>`. |
| Refresh a delivery pull request | `orbit.workflow.refresh` (`orbit_workflow` action `refresh`, `task_id`): refreshes one `blocked` or `review` task's open Orbit delivery PR by merging its base tip as a conflict-free merge commit, then starts required checks on a changed head. A live resident cycle needs the `refresh` right and its mandate's own workspace; other managed runs are refused. It never rebases, force-pushes or lands. Already up to date is a no-op. Refusals start with `task_refresh_refused` for an ineligible status, live run ownership, a missing or multiple PR, a non-Orbit PR, a changed target branch, merge conflicts (with paths), or forge refusal; the PR head is unchanged. | MCP and `orbit tool run` only. |
| Land a task in review | `orbit_workflow` action `land` (`task_id`; operator authority, or a resident cycle holding `merge`): merges the task's delivery pull request at the head whose required checks it just read, under the forge's branch protection, and settles the task to `done`. Refusals answer `task_landing_refused`; a repeated call settles an already merged pull request without merging again | MCP and `orbit tool run` only |
| Submit a catalog job | `orbit_pipeline_invoke` (opt-in `--toolset pipelines` or `machine.mcp.toolsets` in the operator profile; included in `resident`; `job_name` plus `input`, or operator-only `default_input: true` with `workspace`). Returns a run ID; a managed run needs a host-authorized child admission. No MCP wait — an operator session polls `orbit_run` action `show` (operator authority; denied for agent sessions); a session with a shell on the owning host uses `orbit run show <run-id>` instead | `orbit run job <id>` (`--wait` blocks). `orbit.pipeline.wait` is CLI-only |
| Observe/resume workflows | Operator-only `orbit_run` actions `show`, `list` and `resume` (denied for agent sessions; a session with a shell on the owning host uses `orbit run show/history/events/trace/logs/cancel`) | `orbit run show/history/events/trace/logs/cancel`; `orbit run concurrency`; `orbit run extend`; job replay/resume |
| Delivery evidence | `orbit_task_show` with `field: "delivery"` alone and optional `run_id` (read only; needs no operator authority) | What one delivery run committed and landed for one task of this workspace, read only from the host's commit and merge step records: typed status, base/head and landed SHAs, PR number, timestamps and provenance. Missing, inconsistent or foreign evidence is `unavailable` with a reason, never inferred; a local fast-forward records the commit the base is at after the merge when that checkpoint includes it, and an older checkpoint that omits the commit leaves the landed SHA empty. Without `run_id` it reads the newest task-delivery run submitted with the task. It applies only to tasks submitted by a delivery run in this workspace; for any other task, call `orbit_task_show` without `field: "delivery"` instead. Inherited commits require a bounded (64-parent), same-workspace/job/submitted-task retry chain and matching deterministic producer checkpoints/definitions; `provenance.source_run_id` and the source timestamp retain the original commit, while a resumed landing requires its own current host evidence. Execution identity/time can come from bounded (256-event) host step lifecycle audit metadata when the run record has no activity steps; audit metadata never supplies commit/landing bytes. Refreshed candidate heads never replace `commit.head_sha`. Full run details stay on operator-only `orbit_run` action `show` |
| Auto-tasks | `orbit_auto_task action add/list/update/mint` (opt-in `--toolset automation` or `machine.mcp.toolsets` in the operator profile; always reachable via `orbit tool run orbit.auto_task`); `update` `enabled` enables or disables a definition | Those four are also CLI commands (`orbit auto-task add/list/update/mint`). `toggle`, `delete`, `show`, `restore`, `recover`, and `reset` are not on MCP (`orbit auto-task`, or `orbit tool run`); `delete` and `reset` need operator authority |
| Routine enablement | `orbit_routine_control` with `action: "list"` or `"toggle"`; operator authority and explicit `workspace` required | `orbit routine list/show` reads definitions and state. MCP toggle needs the observed `expected_enabled` and `target` plus desired `enabled`, and returns `changed` (`false` when the routine already had that state); after a lost reply, observe state before retrying. A refused toggle or `set_trigger` names a stable code shared with the CLI and dashboard (`routine_not_found`, `workspace_mismatch`, `stale_routine_state`, `stale_routine_trigger`, `target_mismatch`); owner-only routines on a replica are a capability refusal naming the owner. `orbit routine enable/disable <name>` toggles the same field from the CLI for the selected (`--workspace`) or current workspace only (another workspace's routine is refused, so the audit row names the workspace that changed) and is operator-only (an agent is refused); `orbit routine pause/resume` controls the separate host-local pause. |
| Review recovery | `orbit_task_recover` action `reconcile_review` (`inspect`, `submit`, `status`, `accept_baseline`) and `orbit_task_recover` action `review_reset`; operator-only and unavailable to managed runs | `orbit task reconcile-review` and `orbit task review-reset`. Reconciliation judges a recovered delivery's changed merged head; reset closes an open attempt and renews one selected lineage budget with a reason, preserving history. Inspect authoritative state after a lost reply. |
| Blocked-task requeue | `orbit_task_recover` action `requeue` (`id`, `reason`, optional `discard_candidate`); available to operators and to a trusted live resident cycle in its mandate's workspace when that mandate grants `dispatch`. Other managed runs are refused. A resident-cycle requeue must omit `discard_candidate` or set it to `false`; setting it to `true` is refused with `capability_denied`, so only an operator can discard a held candidate. | `orbit task requeue <id> --reason <why> [--discard-candidate]`. Returns a blocked task whose run has stopped to the backlog so its next run resumes the candidate and pull request its failure handoff published, after re-authenticating that publication, or the latest candidate a claim of the task kept, which a later claim that ended without one does not replace (`resumes.source: claim`); a live run or unsettled claim is refused. A changed task specification is refused; `discard_candidate` closes the task's undelivered Orbit pull requests (as `orbit task update --status backlog --discard-candidate` does) and reruns fresh. Nothing is written on a refusal. |
| Human decision requests | `orbit.decision` action `list` and `orbit.decision` action `show` (read only; an agent may see a request, never answer it or set `auto` on a rule). `orbit.task.show` with `fields: ["open_decisions"]` lists one task's open requests. A current rule the operator marked `auto` may answer an exact topic match and records that answer as precedent | `orbit decision list` and `orbit decision show` (read). `orbit decision answer <id> <answer> [--note]` is operator-only, from the CLI or the dashboard. `orbit decision reverse <id>` re-opens a precedent answer. `orbit decision rule-auto <rule> <on\|off>` is the only way to set `auto`, and it is operator-only. `orbit decision consolidate` prints a rule proposal and writes nothing. `orbit decision submit` and `orbit decision channel` manage registered decision channels |
| Experiments | `orbit.experiment.show`, `orbit.experiment.list` and `orbit.experiment.readout` (read only; an agent may see an experiment's arms, event log and per-arm outcomes, never change it) | `orbit experiment show <id>`, `orbit experiment list` and `orbit experiment readout <id> [--metric <name>]` (read). `create`, `update`, `clone`, `start`, `pause`, `resume`, `reweight`, `conclude` and `abandon` are operator-only, as is the CLI-only `orbit experiment delete`, which removes a finished experiment that applied no live treatment. `conclude` stores the readout at that moment on the conclusion event and, when an arm is chosen, files one proposed task that names the experiment, arm, verdict and overlay. It changes no configuration or repository file. |
| Condition explain | `orbit.automation.explain` (read only; `definition`, optional `subject`; opt-in `--toolset automation` or `machine.mcp.toolsets` in the operator profile) | `orbit automation explain <definition> [--subject <key>] [--json]`: a routine's or auto-task's condition over live state with its scope, store prefilter and literal cross-reads, ownership verdict, up to 20 matches (with arm state and remaining hold) and up to 20 closest misses (subjects failing exactly one top-level clause), one subject's top-level `&&`/`||` clause tree with clause and operand values (unreadable values are unknown, never false), and its durable tracking: arm states and holds, stall, last pass and skip, recent fires with their upstream chain, and `self`. Writes nothing. `job:<name>` shows a job's auto-task steps instead: outer bound, revision pin, each step's resolved target auto-task (resolution, digest, enabled, own condition guard) and its waits (`when`, `wait_until`, `expire_when`, `reuse_when`, `require_result`) and step reads; it evaluates no wait. An enabled job's executions run detached and park while a step waits. |
| Condition stall clear | `orbit.automation.clear_stall` is operator-only; agents report a stalled condition instead | `orbit automation clear-stall <definition> --reason <text>`: clears `match_storm`, `too_many_matches`, `loop_suspected` or `oscillating` on the workspace owner, audited. |
| Fleet notices | `orbit.notice.post`, `.close`, `.list` and `.show` on a server that enables the opt-in `notice` toolset; always through `orbit tool run` | `orbit notice post\|close\|list\|show`. Short, expiring, attributed announcements (warn, incident, maintenance, info) for the whole fleet; see [Fleet notices](tool-surface-notices.md#fleet-notices) |
| Host commands | `orbit_command_exec` when advertised and authorized | Explicit argv and an absolute working directory inside the selected workspace checkout (or a linked worktree under `.orbit/state/worktrees/`), returning stdout, stderr and exit status within `timeout_ms`; never a shell string. Requires operator capability and the workspace claim, and is withheld from managed runs. The child receives an allowlisted environment (baseline process context, git author and committer identity, and Orbit's execution envelope), not the server's full environment |
| Distributed drain | Internal runtime protocol; no ordinary MCP tools | `orbit run auto --pull` uses a launch-selected owner route for probe, receipt lookup, task admission, bind, settle and a follower's late effort report for leaves it already settled (`orbit migrate --backfill-claimed-effort`). These six operations have no public schemas, and public calls refuse both canonical and formerly advertised names; client names or initialize metadata cannot enable the route. Matching internal protocol support is required on both endpoints, with no public fallback. Use owner-side `orbit tool run orbit.drain.probe`, `orbit.drain.receipt.lookup` and `orbit.drain.claims` for supported diagnostics under the required identified/operator authority. Do not call pull, bind, settle or the effort report by hand: admission and claim mutations retain machine/run fences. Handoff approval is an owner-dashboard action with no CLI verb or tool. Handoff revocation and claim recovery are operator-only: `orbit task revoke-handoff` and `orbit task recover-claim`, with the tools `orbit.task.recover` action `revoke_handoff` and `orbit.task.recover` action `recover_claim`, which managed runs cannot call. See [distributed-drain-setup.md](setup/distributed-drain-setup.md). |
| Setup and maintenance | Discover any server extensions; do not guess | config, doctor, search reindex, audit, GC, filesystem profiles, skill, routine, sweep, job/activity catalogs, workspace role/sync/publication |
